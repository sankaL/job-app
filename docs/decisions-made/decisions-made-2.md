## 2026-10-15 EDT - High section regeneration: list-item claim splitting and High-only audit codes

- Context: A production High regeneration of a Projects section failed with "Regeneration failed unexpectedly" (`SectionGenerationError: unsupported_scope`, 7 attempts). Two causes. (1) `jev_audit.split_paragraph` split prose only on sentence ends, so a Projects list joined one project's last sentence to the next project's name ("...left unread. - Gust, gustapp.ca."), and items without final full stops (the user asked for no dots) merged whole projects. Jev rejected these mixed claims (`unsupported_employer`, `implausible_claim`) in rounds 1 and 2. (2) In round 3 the escalation LLM audit failed the section for `unsupported_scope`, a code High does not enforce (larger scope and new technologies are allowed job-fit additions at High), and the failure stood. A live Jev replay of the failed writer output, split per item, accepted every claim.
- Decision:
  - Prose sections without entries (Summary, and Projects or other optional sections stored as Markdown) are split into list items and paragraphs first, then into sentences. Wrapped lines join the item they continue. Inside an item, only a bullet marker (`-`, `*`, `+`, `•`) starts a new item; a number followed by `.` or `)` starts one only when the current item is itself numbered. A code review found that treating every numbered line as a marker dropped the year or metric from a wrapped line such as "from\n2019. Built APIs.", so Jev never judged it.
  - At High, the LLM audit validator rejects any issue code outside `HIGH_GROUNDING_ISSUES` (`unsupported_employer`, `unsupported_credential`, `unsupported_date_or_tenure`, `unsupported_role_reframe`, `unsupported_metric`, `implausible_claim`). An off-policy answer gets one bounded output correction, then the fallback model; a final off-policy answer fails closed as `grounding_audit_unavailable`, never as a pass. The High audit prompt names its six codes. Medium and Low keep every code.
  - Escalated prose claims are sent to the LLM audit one per line, so a claim is not read as part of the previous item.
- Not changed: High still fails identity facts, seniority and claims that could not fit the role; Medium and Low auditing is unchanged. Consecutive lines with no list marker and no final full stop still join into one claim.
- Rejected: dropping off-policy codes silently at High (an audit answer the validator cannot trust must fail closed); accepting `unsupported_scope` at High (contradicts the PRD High definition).
